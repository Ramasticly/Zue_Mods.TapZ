### 15.3 Hitboxes, hurtboxes and collision (questions 16–24)

**Box types [CODE].** A frame's hit list is up to **10** entries of five shorts `(type, x, y, w, h)` in `hit[50]` (`type & 127`; if bit 128 of the type is set the fields are 16-bit, else bytes; jogo:31944-31981). Type **1** = hurtbox, type **2** = hitbox (attack box), type **0** = projectile spawn marker (x/y = spawn offset). Every other type is an *action marker* processed by `CheckOptFlag` (flags 3–5, 20, 26–28, 30–34, 37–40, 10–17, 41–125; list in 15.10); its `x,y,w,h` are parameters, not geometry. So there are only two collision box kinds: attack (2) and hurt (1) — plus attack-vs-attack for clashes.

**Geometry [CODE]** (`CheckObjHit`, jogo:2045-2110): horizontal mirror flag `m = (wActFlag & 48) ^ (wObjFlag & 48)`. For the box of object `o`: if `(m & 16) != 0` the box spans `x ∈ [ox - hx - hw, ox - hx]`, else `[ox + hx, ox + hx + hw]` (`ox = o.x >> 16`, integer pixels; `hx, hw` = the box's x and width). Vertically, if `(m & 32) != 0` it spans `[oy - hy - hh, oy - hy]` else `[oy + hy, oy + hy + hh]`. **y grows downward.** Coordinates are relative to the object's position (the character's `PlayerXPos/YPos`, i.e. the foot point), **not** to the sprite origin (`$MID`) or to the image. Facing left (`wObjFlag & 16`) mirrors X; a flipped animation (`wActFlag` bit 16) mirrors again (XOR).

**Intersection test [CODE].** Strict inequalities on all four edges: `a.left < b.right && b.left < a.right && a.top < b.bottom && b.top < a.bottom`; **touching edges do not hit**. No tolerance, no priority, no rounding beyond integer pixels. The function returns on the **first** overlapping pair (loops attacker boxes then defender boxes, in list order) and stores the hit point `iHitXPos/iHitYPos` = midpoint of the two box centres (used for the hit effect). Only the **root object's** boxes are tested — linked sub-objects (`lnk[]`) are not.

**When boxes are tested [CODE].** Only boxes of the **currently loaded pattern** exist (`hit[]` is rebuilt at every pattern load; the flag-bit-16 block of that frame). A pattern without a hit block has `iHitNum = 0` and `iHitCount = 0`. Hit detection runs every tick in md 935 once `bGameStart`; both players must have life > 0 and neither may be in md 923/926/927/928/911 (jogo:23542-23547).

**One hit per pattern; no repeated hits [CODE].** Arming: when a pattern with a hit block is loaded the root's `TCB.iHitCount = 1` and `TCB.iHitFlag` = bitmask of box types; on any resolved hit `iHitCount` is zeroed for both players (jogo:23480; projectiles jogo:23415-23416; clash jogo:23313). Consequently a hitbox that stays active for many frames of **one** pattern hits **once**; a **multi-hit** move is a sequence of **patterns each carrying a hit block** (each re-arms and applies full damage again with combo scaling). A pattern that misses keeps testing every tick for its `time`. There is **no per-target or per-box "already hit" register**; the whole mechanism is `iHitCount`. Hit-stop is applied to both fighters (`iHitStop = PlayerHitStop[atk]`).

**Simultaneous cases [CODE].** *Two boxes in one frame*: the first overlapping pair wins. *Both players hit each other in the same tick* (trade): both `DamageChange` calls run with **OPT1 forced to 0** (jogo:23457-23459); the body-hit loop runs victim 0 then victim 1 so index 1 wins a double KO. *Clash* (attack box vs attack box, `CheckObjHit(…, true)`): skipped if either ANO is 27/28; needs opposite facing, `iTimer > 0`, and both ANOs < 40 or both ≥ 40 (jogo:23289-23306); both fighters get hit-stop, both `iHitCount` are cleared, spark effect 3 and SE 9 play (unless a participant is in md 911–915), **no damage**; if a participant has `SpecialKind & 2` ("NO_TRADE") the opponent is forced into the reaction from the counter-user's `charHDAT3[0][13]` (types ≥ 30 → md 877 else md 876; jogo:23486-23516). *Projectile vs fighter*: a projectile that overlaps a defender's attack box (defender ANO ≥ 40) is absorbed with no damage if the defender's `OptData[0] % 50 != 0` (jogo:23390-23402); projectile attack boxes against each other cancel (SE 9, jogo:23430-23443).

**Invulnerability, dodge, teleport, throws, guard [CODE].** Hits are skipped when the defender's `wObjFlag & 8` (set on alternating frames during md 876 hit-stop, md 898/899 invulnerable pose and the ThrowDamage path, which is dead code), when either life ≤ 0, in md 923/926/927/928/911, and obviously when the defender's current frame has no type-1 box (an invulnerable animation is simply one without hurtboxes). Evades (SpecialType 18/19) vanish via md 865. Hit flags 39/40 teleport instantly (`CheckOptFlag`). Guard: see 15.4. Throws are ordinary hits plus the "grabbed overlay" objects (md 939–941) that hit through the projectile path (jogo:23424).

**Walls and screen [CODE].** Variables: `iBackXPos` (camera left in world px·65536), `iBaseXPos` (base position: 0 = left world edge, 62849024 = right), `iBackXOffset` (camera offset used by cutscenes), `DamageWall` (a reaction hit the wall), `bForceWall` (forces wall detection anywhere; reset every tick in md 935 and set by cutscene kind 6). Details of the wall test and the WALL/COMP behaviour are in 15.5 and 15.6.
