### 15.4 Damage and life loss (questions 25–33)

Source of truth: the game class `TCBManajer` (file `TCBManajer.java`, "jogo:NNNN" = line). Tags: **[CODE]** read in the game code, **[INFERRED]** deduced, **[UNKNOWN]** not determinable from the code. The game is strictly **1 vs 1**: "several targets" does not exist.

**Call chain [CODE].** The hit-resolution task is md 935 (`case 935:` jogo:23194), run every tick. Damage and reaction are read from the attacker's `ObjReq` at hit time: `OptData[0]` = damage, `OptData[1]` = OPT1 (loaded per animation pattern in `_ActReqMain`, jogo:31993-32014; a pattern with no `$OPT` block gets `wOptFlag = 0` and `OptData[0..3] = 0`, so a hitbox frame without `$OPT` deals **0 damage with OPT1 = 0** — group 0, reaction 0 — and still counts as a hit). `DamageChange(gw, atk, tgt, bApply, bBody, atkAno, dmgByte, opt1, optFlag)` (jogo:3466) is called for projectiles and grab follow-up objects at jogo:23424 and for body hits at jogo:23464. If both players hit each other in the same tick, OPT1 is **forced to 0 for both** (jogo:23457-23459: a trade always uses reaction 0 / effect-sound group 0). The body-hit loop runs victim 0 first then victim 1; if player 1's hit KOs player 0, player 0's own hit is skipped by the early-out "attacker life ≤ 0" at jogo:3478-3480, so **index 1 wins a double KO**.

**`$OPT` bytes [CODE].** `d0` = base damage 0..255 (jogo:3496; also the heal amount of hit flag 34 at jogo:2313 and the self-damage amount of flag 32 at jogo:23261). `d1` = OPT1 = `group*50+index` (jogo:3518-3519). `d2` ≠ 0 turns on the per-pattern tween of rotation/alpha/zoom/offset (`_Hokan`, jogo:32108; visual only). `d3` is written and **never read**. OPT1 values **250..255 index `HitEffectActNo[5]` out of range → the game crashes** (jogo:3529); the editor limit is 249.

**Formula [CODE], all integer math, left-to-right truncation:**
1. If the attacker has hit flag 28 active (`PlayerState & 262144`): `D1 = D0` (no multipliers, no minimum).
2. Else if `D0 != 0`: `def = DeffenceMul[tgt] + AddDeffencePer[tgt]` (the second term is never written, always 0); `def = max(def, 0)`; `D1 = AttackMul[atk] * D0 / 100 * (100 - def) / 100` (jogo:3496); if the attacker is in rage (`AngryOn[atk]`) `D1 = charHDAT37[0][0] * D1 / 100` (jogo:3498-3500); `if (D1 < 2) D1 = 2` (jogo:3503-3505). If `D0 == 0`, `D1 = 0`.
3. If the attacker's ANO is **92**, `D1 = 0` (the hit and reaction still happen; jogo:3514).
4. **Combo scaling** (jogo:3529-3560): `c = ComboCount[atk]` (before this hit); `idx = c` if c < 2 else `min(c,15) - 2` (sequence for c = 0,1,2,3,4… is idx 0,1,0,1,2,…,13); if `D1 != 0`: `D2 = (short)LE16(gamedata HDAT 5, row 2, idx) * D1 / 100`, and `D2 = 1` if the result is 0. Applies to flag-28 hits too. The table values live in the data pac **[UNKNOWN]**.
5. Cap and apply on hit only (jogo:3806-3815): `D3 = min(D2, Life[tgt])`; `TotalDamage[tgt] += D3`; `LIFE_DEC(tgt, D3)` (jogo:3878; `LIFE_DEC` at jogo:29164 acts only when `iTimer != 0` and the other player is alive). `Life` is clamped ≥ 0 (≥ 1 in `iPlayMode == 2` and in mission-life checks).
6. Side effects of `D3`: defender gauge `SYNCHRO_ADD(tgt, charHDAT1[0][3]*D3/charHDAT1[0][2])` and `ANGRY_ADD(tgt, 10)`; attacker gauge `charHDAT1[0][1]*D3/charHDAT1[0][0]`; score (animations 27..66, not flag 37).

**Attack/defense stats [CODE].** `AttackMul[p] = GetAttack + GetCardAttack` (jogo:5513-5515); `GetAttack` (jogo:27721) = `charHDAT3[0][12]` + sum of `charHDAT7[i][1]` for i up to `min(Level+AddLevel, 98)`; `GetDeffence` (jogo:28191) = `[0][14]` + sum of `[i][3]`. Values are percentages [INFERRED from `/100`]. **No term depends on distance, the defender's state/position or the move's index** — only `AttackMul`, `DeffenceMul`, rage, combo count, animation 92 and flag 28.

**Hit flags that change damage [CODE].** 26 = skip the guard check (unblockable). 27 = blocks the cancel logic while `CancelTime > 0`. 28 = raw damage (above). 32 = self-damage frame: when `iHitCount != 0`, both alive and `PlayerState & 1048576` (jogo:23260-23263) → `SelfDamage(p, OptData[0], OptData[1])` (jogo:30833), which sets `Life = 1` if `Life <= d` (it **cannot kill**) and ignores attack/defense. 33 = sets a state bit nobody reads (no effect). 34 = heal: `LIFE_ADD(p, OptData[0])` (capped at max life; needs `iTimer != 0` and the opponent alive). 37 = no combo count and no score (damage still uses combo scaling). 38 = chain uses `DamageHitActNo` instead of the HDAT 4 lookup. These bits live in `PlayerState[player]` and are **cleared every tick and re-applied from the current pattern** (`PlayerTail`, jogo:29884), so they only matter in frames that carry the hit flag.

**Guard [CODE].** Defender states allowed to guard: not in md 876/877, ANO not in {6,7,8,9,82,83}, ANO ≤ 19 or in {25,80,81}, `iTimer != 0`, attacker has no flag 26 (jogo:3562-3585). Humans guard by holding a direction away from the attacker; CPUs use probabilities; **height (high/low) is ignored**. On guard: no reaction table, `DamageMove = GuardHitBack` (13, groups < 3), `GuardCancelTime = PlayerHitStop + 5`, chip damage only if the attacker's ANO ≥ 40: `max(D2/5, 1)` scaled by `GuardHardness` (never written → 0) then `max(.., 2)` when `D2 != 0`; no combo increment; hit effect Ano 2 with SE 8.

**Never-assigned values [CODE].** `AddDeffencePer`, `GuardHardness`, `SynchroAttackPer` are read but never written (always 0); `DamageHitBack` is only ever assigned 0 (the hit push-back is always 0); `ThrowDamage` (jogo:187) is **never set to true** anywhere — every `ThrowDamage == true` branch is dead code in this build.

**Per-event rules [CODE].** Damage is applied **once per resolved hit event**, and a hit event happens at most **once per animation pattern** (next section). Projectile damage uses the **owner's** `AttackMul` and `PlayerState`; projectile hit flags land on the owner's `PlayerState`. A projectile that overlaps a defender's attack box (defender ANO ≥ 40) is absorbed with no damage if the defender's `OptData[0] % 50 != 0` (jogo:23390-23402); projectile vs projectile attack boxes cancel with SE 9 (jogo:23430-23443).

**KO and hitstop [CODE].** If `Life[tgt] <= 0` after damage the OPT1 reaction is **overridden**: `DamageType = 2, DamageIndex = 0, DamageTime = 0, DamageOldType = 2`, md 876 (jogo:3993-4000); in md 876 a KO in type 2 becomes type 29 (jogo:20989-20992); after the reaction the game plays ANO 24 and enters md 888 → 889 and stays down. Hitstop: `iHitStop = PlayerHitStop[atk]` for **both** players (6 for basic attacks, 10 for specials); group 3 uses half for body hits, group 4 none; projectiles give the target full hitstop and the projectile half; it decrements at the start of md 935 and pauses animation and reaction movement; in md 876 hitstop the defender jitters ±1 px. Invulnerable when: defender `wObjFlag & 8` (alternating frames in md 876 hitstop), either player's life ≤ 0, either player in md 923/926/927/928/911 (the whole hit step is skipped), `iTimer == 0` (no life loss). Hits **during a reaction are allowed** (no untechable window): `DamageChange` resets `DamageTime/Index` and re-enters the reaction.

**What the app's simulator omits [CODE-compared].** `BattleSim.applyDamage` matches flag 28, min-2, ANO 92, combo scaling, life cap and combo count; it omits the rage multiplier, guard/chip, score and gauge gain.
