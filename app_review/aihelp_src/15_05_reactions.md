### 15.5 Reactions, COMP and recovery (questions 34–45)

**Resolving OPT1 [CODE].** `group = OPT1 / 50`, `index = OPT1 % 50` (jogo:3518-3519). `index >= 30` → md 877 with `DamageType = index - 30` and the **attacker's** character table HDAT 14+type; `index < 30` → md 876 with `DamageType = index` and the gamedata table HDAT 10+type (jogo:3824-3828, 20995, 21264). Example: **OPT1 116 = group 2 (strong), index 16 = game-wide reaction 16**; OPT1 52 = group 1, index 2.

**Groups [CODE].** `HitEffectActNo = {0,0,1,0,-1}`, `HitSound = {3,4,6,3,7}`, `GuardEffectActNo = {2,2,2,2,-1}` (jogo:601-603). Group 4: no effect, no sound, no combo increment. Push-back (`DamageMove`) only for groups < 3 and it is always 0. Hitstop: group 3 half (body hits), group 4 none. Combo count (cap 99) increments only when the effect ANO is 0 or 1 and the hit is not flag 37. Sound is SE 8 for any effect other than ANO 0/1, else `HitSound[group]`. A hit with OPT1 forced by a trade or clash is always group 0.

**Where the tables are [CODE].** Gamedata HDAT 10..39 come from the data pac `gamedata` (`InitGameData`, jogo:29133-29134); character tables are HDAT 14..33 inside `ChrGameData[player+3]`. **No reaction rows are literals in the code**; all rows are in the data pacs. Table header = u16 count then 8-byte entries {pos u32, xsize u16, ysize u16}; each reaction is its own table with xsize 14 and ysize = number of steps. `piGameData` is a `short[]` of unsigned bytes; the code casts `(byte)` where it needs signed.

**The 14 columns [CODE].** 0 `DUR_C` (ticks while `PlayerYPos == 15728640`, i.e. on the ground); 1 `DUR_A` (ticks while airborne or below the floor, jogo:21201-21207); 2 `ANO` (signed; negative flips the defender: `wObjFlag ^= 16` and uses `-ano`, jogo:21002-21008); 3–6 ground `xspeed, yspeed, xaccel, yaccel` (signed); 7–10 the same for air (used when `PlayerYPos < 15728640`); 11 `COMP`; 12 `WALL`; 13 `VOZ` (signed; `> 0` plays `Voice(1, player, v)` when the row is entered, jogo:20996-20999).

**Special values [CODE].** *Speeds/accels:* `-1` keeps the current `DamageX/YSpeed`/`Accel` (jogo:21033-21060); `-2` on a speed = `rawUnsigned(OldType row OldIndex, same column) / 2` (**raw, not scaled by 128/10, and read as an unsigned byte** — a quirk: a previous speed of −40 is read as 216); `-2` on an accel = half of the current accel. Normal values are `v*128/10` (truncating): one unit = 1/128 px per tick scaled by 10, i.e. tenths of a pixel per tick (`v = 10` → 1 px/tick). *Duration 255:* the row holds until `DamageTime >= 255`, then switches to `DamageType 2, Index 0` (in md 877 type 2 reads the attacker's character table HDAT 16; jogo:21208-21213, 21492-21496). *Duration 0:* lasts 1 tick (`max(dur,1)`).

**Row stepping [CODE].** Entering a row loads speeds (`DamageTime` 0 → 1); each non-hitstop tick checks `DamageTime >= dur`, otherwise `DamageTime++`; at the end of a row `DamageIndex++`, `DamageTime = 0` (jogo:21215-21217). Hitstop ticks do not advance the row (the entry load still runs). Past the last row: still moving vertically (`DamageYSpeed != 0`) → alive: type 13 (md 877 explicitly switches to md 876); dead: type 2 / lying; `DamageYSpeed == 0` → alive: `DamageEnd` and md 864 (control returns); dead: ANO 24, md 888.

**COMP [CODE]** — evaluated every tick after movement when `iHitStop == 0` (jogo:21095-21200, 21369-21482):
- **0**: if `PlayerYPos > 15728640` clamp to the ground and clear `PlayerAir`; nothing else.
- **1..49 with `WALL` not 2/3 and `!bForceWall`**: COMP **11** → when `Y > ground` or (`YSpeed <= 0` and `YAccel <= 0`): `Y = ground`, ANO 24, md 888 (lying). Otherwise, on reaching the ground (`Y >= ground`): snap, play SE 11; if COMP is 12 and `DefensiveFlag == 1` (the player pressed a mask-16640 button while airborne) and alive → `DamageEnd`, ANO 22, md 886 (air tech); else switch `DamageType = comp`, `Index 0`, `Time 0`. In md 877 `comp >= 30` switches to the attacker's character table `comp - 30`; below 30 it goes to md 876 gamedata type `comp`. In md 876 `comp >= 30` sets `DamageType = comp` which reads HDAT 40–59 — **undefined/out of range**.
- **1..49 with `WALL` 2 or 3 (or `bForceWall`)**: if `Y > ground` → SE 11, snap to the ground, `DamageOldIndex = 0`, `DamageOldType = comp` (md 876) or 16 (md 877), `DamageType = 12` (the bounce reaction). Else, if at a world-edge wall (below), set `DamageWall = true` and switch to type `comp`.
- **≥ 50 (including 255)**: if `Y > ground`: SE 12, ANO 13, `DamageEnd`, md 893 (hard-landing stun, jogo:21173-21184).
- The wall test (both need `(PlayerState[0]|PlayerState[1]) & 1 == 0`, i.e. no flag-1024 blackout): left `X <= iBackXPos + halfWidth && (iBaseXPos <= halfWidth || bForceWall)`; right `X >= iBackXPos + 31391744 - halfWidth && (iBaseXPos + halfWidth >= 62849024 || bForceWall)`. Md 876 also requires `DamageYSpeed <= 0`; md 877 treats `WALL == 3` as a permanent wall and handles `comp >= 30`.

**`WALL` column [CODE].** 0/1: the wall does not restart the reaction; 1 also makes the camera pan to follow the wall-hit player (md 19, jogo:15380-15426). 2/3: touching the wall (or landing) restarts the reaction at `COMP`; 3 additionally keeps `iBaseXPos += iBackXOffset` (no recentre). `bForceWall` is reset every tick in md 935 and set by cutscene effect kind 6 (jogo:25231-25232).

**md 876 vs 877 [CODE].** Same pipeline (jogo:20983 vs 21259). Differences: table source (gamedata HDAT 10+type vs the attacker's character HDAT 14+type); 877 first forces ANO 0 if the new ANO equals the current one (restart) and calls `ChrSePlay`; type 2 → 29 on KO only in 876; the wall branch differs as above; landing sets `PlayerAir = false` in 876 but not in 877's COMP 11/generic landing; bounce `DamageOldType` is `comp` in 876 and 16 in 877; 877 ending airborne explicitly moves to md 876 types 13/2. Character reactions (877) can chain to gamedata types 1–29 or character types 30–49; gamedata reactions (876) only to gamedata types 1–29.

**DamageChange vs DamageEnd [CODE].** `DamageChange` (jogo:3466) starts a reaction; `DamageEnd` (jogo:4043) ends it and zeroes `PlayerAttack`, `SpecialKind/Type`, `DamageType/Index`, sets `ComboCount[1-p] = 0`, `HitActNo = -1`, `BulletAction[p][0] = 0`, `ThrowDamage = DamageWall = false`, `DamageHitSpecialType = 20`. It does **not** touch `DamageTime`, the speeds, `DamageOld*` or `DamageMove`. State variables: progress = `DamageType/Index/Time`; chain origin = `DamageOldType/OldIndex`; persistent speeds = `DamageXSpeed/YSpeed/XAccel/YAccel` (not cleared by `DamageEnd`); landing = `DamageWall`, `bForceWall`, `DefensiveFlag`; source = `DamageHitActNo`, `DamageHitSpecialType`.

**Return to normal [CODE].** Table ends with `DamageYSpeed == 0` and life > 0 → `DamageEnd` → md 864 → md 872. Airborne at the end → type 13; md 864 with `Y < ground && !PlayerAir` plays ANO 89 and md 886 (jogo:20748-20755). Hard landing md 887/893 (jogo:22150-22281). Lying: md 889 waits for the lying animation, md 890 does `DamageEnd` and plays ANO 25, md 894 returns to md 864 (jogo:22166-22199, 22283-22288). A new hit is possible any time a hurtbox overlaps; `ComboCount` resets only on the defender's `DamageEnd`.

**KO table lookups and trades.** KO forces type 2 whatever OPT1 was (see 15.4). A trade forces OPT1 = 0 (see 15.4). Clash of attack boxes (below) puts the loser in a reaction taken from the counter-user's `charHDAT3[0][13]` (types ≥ 30 → md 877, else md 876): this is the reaction used by `ATK_FLAGS` bit 2 (NO_TRADE), and it is that **number** the app prints in the GOLPE SET explanation.
